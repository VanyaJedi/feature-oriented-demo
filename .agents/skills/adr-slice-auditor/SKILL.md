# ADR Slice Auditor

Прочитай [архитектурный ADR](../../../docs/adr/0001-architecture.md), затем изменяемые
файлы и их ближайшие зависимости. Пути в командах ниже отсчитываются от корня репозитория.
При изменении импортов сверяйся с `tsconfig.app.json`, `vite.config.ts`,
`eslint.config.js` и `eslint/architecture.js`.

## Проверка границ

- Направление: `app → pages → features → infrastructure → shared`; вышележащие
  слои недоступны нижележащим, включая type-only зависимости.
- Между разными фичами допускаются только type-only импорты и реэкспорты.
  Runtime-токен соседней фичи не является исключением.
- Разные страницы не импортируют друг друга. Infrastructure/shared могут
  использовать соседей своего слоя, но не образуют циклов.
- Внешний доступ к фиче проходит через публичные входы каталогов, без корневого
  barrel и deep-import внутренних файлов. ESLint проверяет не все эти ограничения.

## DI и ответственность

- Учебный контейнер хранит готовые экземпляры. Не добавляй автосборку или lazy
  API из других библиотек, если задача этого не требует.
- Feature-регистрации принимают `Container` аргументом. App выбирает реализации;
  `src/main.tsx` запускает регистрацию до рендера. Импорты не регистрируют сервисы.
- Зависимость регистрируется до создания потребителя. Сервис получает её через
  конструктор, а не через вызов контейнера внутри сервиса.
- Контракт доставки принадлежит checkout; delivery реализует его, app связывает их.
- Hooks используют DI для своих сервисов, координируют действия и состояние.
  Сервисы содержат бизнес-операции, UI отображает результат.
- В демо нет React Query, Zustand, роутера и SSR. Не требуй их установки: текущее
  локальное состояние и моковые данные намеренно упрощены. При появлении backend
  отделяй серверный кэш от клиентского состояния.

## Изменения и проверка

Если задача разрешает исправления, размещай код по ролям из ADR и обновляй
импорты после переноса. Следуй существующим именам `*.service.ts`, `use*.ts`,
`*.types.ts`, `tokens.ts`. Не добавляй пустые каталоги и лишние абстракции.

Для изменений импортов или кода запускай `npm run lint` и `npm run typecheck`.
При изменении ESLint-правил также запускай `npm run test:lint`. Для правок только
документации проверь ссылки и соответствие коду; сборку повторять не требуется.
Если нужная проверка недоступна, укажи её и причину.
